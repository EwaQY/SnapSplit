# 多人分摊记账 App MVP PRD V4.0

## 1. 产品概述

### 1.1 产品定位
一款本地优先的多人分摊记账 App，核心能力：

1. 在单设备上创建账本，添加多个虚拟分摊人，按商品/账目维度分摊。
2. 支持手动录入、编辑，以及通过 AI 识别小票、购物截图辅助批量录入。
3. 购物单作为多个账目的集合，底层为"账本 → 购物单 → 账目"，UI 上购物单与账目同层级展示。
4. 提供债务净额展示与转账/结算记录，不做最优转账算法。
5. 支持周期预算管理（自然月），跟踪"我的消费"进度。
6. 引入周期概念：历史周期数据自动归档，不可编辑/删除，仅提供查看功能。
7. 所有业务数据存储在本地 SQLite。

### 1.2 MVP 目标
- 跑通：首次启动生成本地账户 → 创建账本 → 添加虚拟成员 → 录入/识别 → 分摊 → 保存 → 时间线展示 → 结算 → 转账核销。
- 验证：单设备多人分摊 + 商品级分摊 + AI 辅助录入 + 周期预算管理是否真实好用。
- 控制：不做注册登录、邀请、同步、权限、通知、多币种、复杂统计、导出导入、加密等非核心功能。

### 1.3 核心用户场景
- 室友/情侣日常共同消费，在一台设备上按商品分摊。
- 朋友聚餐、旅行、合买，部分商品均摊、部分独享。
- 用户上传小票或电商订单截图，AI 识别为多个商品，确认后入账。
- 多人之间出现欠款，通过转账/结算记录核销。

## 2. 范围

### 2.1 MVP 包含
- 首次启动自动生成本地账户"我"，可编辑昵称、头像。
- 虚拟成员管理：可添加、改名、编辑、软删除账本内分摊人。
- 创建多个本地账本。
- 本地账本时间线，展开展示账目/购物单。
- 手动录入单账目、多账目购物单。
- AI 批量多图识别，一张图默认一个购物单。AI 服务通过前端传入 API key 调用。
- 商品级付款人、参与人、分摊明细设置。
- 折扣/附加费摊入商品最终金额，不生成独立账目。
- 标签系统：全局共享标签。
- 结算板：展示"我"视角两两净额，以及全局成员应收/应付。
- 转账/结算记录：核销欠款，不计消费。
- 周期预算：默认自然月，统计"我的消费"，支持设置预算金额，超支警告。
- 纯本地 SQLite 存储。
- 历史周期数据自动归档，不可编辑/删除，仅提供查看功能。

### 2.2 MVP 不包含
- 注册、登录、退出登录、切换账户。
- 账号 ID 检索、邀请链接、二维码、加入账本。
- 后端服务、服务器同步、多设备共享。
- 实时协同、冲突合并。
- 权限控制、角色管理 UI。
- 推送通知、实时动态。
- 多币种、汇率换算。
- 搜索、筛选、图表统计、数据导出、数据导入。
- 回收站 UI。
- 忘记密码、账号验证、账号找回。
- 保存后拆分/合并购物单。
- 跨购物单批量编辑。
- 最优转账算法。
- 结算锁定期。
- 复杂折扣/附加费按高级规则分摊。
- 本地数据库加密。
- 在线/离线状态提示，UI 中不出现"在线""离线"概念。

## 3. 术语与核心概念

| 术语 | 定义 |
|---|---|
| 本地账户/我 | 当前设备上的唯一操作者。首次启动自动生成，不可登录、不可切换。 |
| 虚拟成员 | 账本内的分摊人，不是可登录账户，不能在设备上切换成该用户。 |
| 账本 | 多人分摊记账的顶层容器。 |
| 账本成员 | 加入账本的"我"或虚拟成员。MVP 无权限区分。 |
| 购物单 | 一次购物或一张小票/截图的集合，底层包含多个账目。 |
| 账目/商品 | 最小记账单位，也是分摊基本单位。 |
| 付款人/垫付人 | 实际支付该账目金额的人。 |
| 参与人 | 需要承担该账目金额的人。 |
| 分摊明细 | 每个参与人各自的分摊金额，底层保存具体金额。 |
| 转账/结算 | 特殊记录类型，表示成员之间资金转移，不计消费，只影响余额。 |
| 时间线 | 账本内按时间倒序展示账目/购物单的主界面。 |
| 结算板 | 展示"谁欠谁多少"或成员应收/应付的页面。 |
| 降维展示 | 单账目购物单在 UI 上不显示为购物单，而直接显示为账目。 |
| 周期 | 默认自然月（1号-月末），用于划分数据的时间范围。 |
| 已归档 | 进入新周期后，历史周期的账目、购物单、转账记录、预算自动归档，不可编辑/删除，仅提供查看功能。 |
| 归档 | 标签被归档后，不再出现在新账目的标签选择器中，但历史账目的标签引用保留不变。 |

### 3.1 层级关系
- 底层：账本 → 购物单 → 账目。
- UI：购物单与账目同层级展示。
- 单账目购物单：底层仍为购物单，UI 降维为账目。
- 多账目购物单：UI 显示为购物单，可展开查看子账目。
- 转账记录：与购物单/账目同层级展示，但类型不同。

### 3.2 数据分类与生命周期

| 数据类型 | 生命周期 | 说明 |
|---------|---------|------|
| 账目/购物单/转账记录 | 按周期归档 | 当前周期可编辑/删除，历史周期自动归档，不可修改 |
| 预算 | 按周期归档 | 当前周期可编辑，历史周期自动归档，预算不可变 |
| 标签 | 手动归档 | 跨周期复用，用户主动归档不影响历史账目引用 |
| 虚拟成员 | 手动软删除 | 跨周期复用，软删除后历史账目保留引用 |
| 账本 | 不归档 | 容器，持续使用 |

## 4. 用户角色与权限

### 4.1 本地账户
- 设备上只有一个"我"。
- 首次启动自动生成，可编辑昵称、头像。
- 不需要手机号、邮箱、密码。
- 不可退出登录，不可切换账户。

### 4.2 虚拟成员
- 虚拟成员属于账本成员，可作为付款人、参与人、收款人。
- 虚拟成员不能登录、不能切换、不能操作 App。
- 虚拟成员可跨账本复用底层人员资料，但每个账本独立维护成员关系。
- 虚拟成员可软删除；历史账目保留引用，并显示"已删除成员"。

### 4.3 权限
- MVP 只有当前设备上的"我"可以操作。
- "我"可创建、编辑、删除当前周期内的账目、购物单、转账记录、成员。
- 历史周期数据自动归档，不可编辑/删除。
- 删除前必须强提示。

### 4.4 数据可见性
- 当前设备上的"我"可见所有本地账本、账目、购物单、结算记录。
- 虚拟成员无数据可见性概念。

## 5. 核心业务流程

### 5.1 首次启动
1. 用户首次打开 App。
2. 系统自动生成本地账户"我"。
3. 用户可设置昵称、头像。
4. 进入账本列表。
5. MVP 不提供注册、登录、找回密码、账号验证。

### 5.2 创建账本与成员
1. 用户可创建多个本地账本。
2. 创建账本时，"我"自动成为账本成员。
3. 用户可手动添加虚拟成员。
4. 虚拟成员可编辑名称、头像。
5. 虚拟成员可软删除。
6. MVP 不做邀请链接、二维码、账号 ID 检索、加入账本。
7. MVP 不做删除账本、退出账本、移除成员。

### 5.3 手动录入单账目
1. 进入录入页。
2. Header：时间、付款人、备注/默认分摊规则。
3. Body：一行商品/账目。
4. 默认付款人=当前用户"我"；默认参与人=账本全部未删除成员；默认均摊。
5. 保存后：底层创建单账目购物单，UI 降维展示为账目。

### 5.4 手动录入多账目购物单
1. 进入录入页。
2. 填写第一行后点击"+ 添加新账目"。
3. 系统自动变为购物单模式。
4. 可设置购物单标题、整体备注。
5. 每个账目独立设置付款人、参与人（默认均摊）。
6. 保存后生成一个购物单，包含多个账目。

### 5.5 AI 批量多图录入
1. 用户一次上传最多 9 张图片。
2. 全屏同步等待，提示"请勿退出或熄屏"。
3. AI 逐张识别。
4. 一张图默认生成一个购物单：
   - 图内多个商品 → 多商品购物单。
   - 图内只有一个商品 → 单商品购物单，UI 降维为账目。
5. 识别结果进入统一确认页，按图分组。
6. 用户可增删改、调分摊、改付款人、改标签。
7. 确认保存后才入账。
8. 单张失败可重试或跳过，已识别结果保留；全部失败可转手动录入。
9. MVP 不保存原图，识别后图片立即删除。
10. AI 服务通过前端传入 API key 调用。

### 5.6 编辑与删除
- 当前用户"我"可编辑/删除当前周期内的账目、购物单、转账记录。
- 历史周期数据自动归档，不可编辑/删除，仅提供查看功能。
- 修改/删除当前周期数据会影响当前余额，保存前强提示。
- 删除购物单时提示"确认删除此购物单及包含的 N 个商品吗？"
- 删除采用软删除，记录 `deleted_at`。
- 删除父实体时，应用层在同一事务内软删除所有子实体。

### 5.7 结算与转账
1. 结算板展示当前用户"我"视角：
   - 我欠 X 多少。
   - X 欠我多少。
2. 全局视图展示每个成员应收/应付。
3. 不做最优转账算法。
4. 点击"我欠 B 150 元"可弹出"向 B 结清"。
5. 自动生成转账记录：金额 150，付款人"我"，收款人 B。
6. 转账记录不计消费，只影响余额。
7. 转账记录仅限当前周期内可编辑/删除，历史周期记录自动归档。
8. 允许创建任意成员之间的转账记录，默认"我 → 对方"。

## 6. 功能需求详述

### 6.1 本地资料与设置
- 首次启动自动生成本地账户"我"。
- 可编辑昵称、头像。
- 不展示账号 ID、手机号、邮箱。
- 不提供退出登录。
- "我的/设置"页展示：本地资料、数据说明、关于。

### 6.2 成员管理
- 账本内成员包括"我"和虚拟成员。
- 可添加虚拟成员：昵称必填，头像可选。
- 可编辑虚拟成员昵称、头像。
- 可软删除虚拟成员。
- 删除成员后，历史账目中仍保留该成员引用，显示"已删除成员"。
- 虚拟成员可跨账本复用底层人员资料，但每个账本独立维护成员关系。

### 6.3 账本管理
- 支持创建多个账本。
- 首页展示账本列表，最近访问优先。
- 账本字段：名称、创建者、创建时间、成员列表、状态。
- MVP 不做删除账本、退出账本、移除成员。

### 6.4 购物单与账目
- 购物单字段：标题、商家、发生时间、创建者、默认付款人、默认参与人、备注、来源。
- 账目字段：名称、数量、单价、最终金额、标签（多个）、付款人、备注。
- 数量、单价、总价均保存。
- 若数量×单价与总价冲突，以总价为准。
- 分摊以最终金额为准。
- 单账目购物单 UI 降维为账目。

### 6.5 统一录入/编辑/确认页
- 手动录入、AI 确认、编辑页 UI/UX 保持一致。
- 结构：
  - Header：时间、付款人、整体备注/默认分摊规则。
  - Body：动态清单流，每行一个商品/账目。
  - Footer：+ 添加新账目、总金额汇总。
- 每个商品行可展开编辑：
  - 名称、金额、标签、付款人、参与人。
- 默认值：
  - 付款人=当前用户"我"/上传者。
  - 参与人=账本全部未删除成员。
- 用户可批量应用默认值到当前所有商品，之后每个商品独立修改。
- Header 默认值随购物单保存为快照；编辑页重进时恢复快照，加新行/批量应用以快照为准。
- 不搞父子覆写逻辑，每个商品生来独立。

### 6.6 分摊规则
- 分摊基本单位：商品/账目。
- 支持指定参与人。
- UI层支持分摊方式选择：均摊、按比例、按金额。
- 默认均摊：参与人平均分担金额。
- 保存时，应用层根据用户选择的分摊方式计算各参与人的具体金额。
- 底层只保存 item_participant 表的 share_amount（具体分摊金额），不保存分摊方式。
- 付款人可以不在参与人中，例如 A 垫付但 B 独享。
- 均摊除不尽时：
  - 优先将差额分配给垫付人。
  - 若垫付人不在参与人中，则调整给参与人中金额最大者。
  - 保证总账永远能平。

### 6.7 折扣、配送费、附加费
- 不生成独立商品/账目。
- 不记录中间信息。
- 直接摊入商品最终金额。
- 规则：
  - 按各商品原始金额比例摊到每个商品。
  - 分位四舍五入。
  - 差额调整到金额最大的商品。
  - 若只有一个商品，直接计入该商品最终金额。
- 用户手动修改时，改的是商品最终金额。
- AI 可临时识别全局附加费/折扣用于计算，但保存时不持久化中间字段。

### 6.8 标签
- 标签打在账目/商品上，购物单不单独打标签。
- 一个账目可打多个标签（多对多关系）。
- 统计按子账目聚合。
- 标签全局共享，所有账本使用同一套标签。
- 可新建、编辑、归档。
- 归档：标签被归档后，不再出现在新账目的标签选择器中，但历史账目的标签引用保留不变，UI 正常显示原始标签名称。
- 统计：按标签独立汇总其关联账目的最终金额，各标签合计不要求等于总消费。

### 6.9 时间线
- 按日期倒序。
- 多商品购物单展开展示子账目。
- 子账目 ≤5 个：全量展开。
- 子账目 >5 个：显示前 3–4 个，末尾显示"... 等共 N 项商品（点击展开全部）"。
- 单账目购物单降维为账目展示。
- 同一批多图生成的多个购物单按创建时间倒序，独立展示，不显示"批次"。
- 历史周期数据标记为"已归档"，不可操作。

### 6.10 结算板
- 当前用户"我"视角：我欠 X / X 欠我。
- 全局视角：每个成员应收/应付。
- 不做最优转账算法。
- 点击债务可快捷生成转账记录。

### 6.11 转账/结算记录
- 特殊记录类型，不属于购物单消费。
- 字段：付款人、收款人、金额、时间、备注、创建者。
- 不计入消费统计，只影响余额。
- 仅限当前周期内的记录可编辑/删除，历史周期记录自动归档。
- 允许任意成员之间创建，默认"我 → 对方"。

### 6.12 周期预算
- 默认自然月（1号 00:00:00 - 月末 23:59:59）。
- 统计范围：用户作为「付款人」的所有账目最终金额。
- 预算粒度：全局级别，每个账本共享预算。
- 预算定义：仅统计"我的消费"（当前用户作为付款人的账目）。
- 预算设置：用户可设置每月预算金额（单位：元）。
- 预算展示：账本列表页顶部展示当前月份预算进度（已消费/预算）。
- 超支警告：仅提示已超支，不阻断记账。
- 历史周期数据自动归档，预算基于实际发生额，不可变。
- 支持查看过去几个月的预算使用情况（已归档）。

### 6.13 AI 识别
- 支持批量多图，单次最多 9 张。
- 格式：jpg/png/webp，单张 ≤10MB。
- 全屏同步等待，提示"请勿退出或熄屏"。
- 识别后进入统一确认页。
- 确认保存后才入账。
- MVP 不做草稿。
- 不保存原图，识别后图片立即删除。
- 单张失败可重试/跳过。
- 全部失败可转手动录入。
- AI 服务通过前端传入 API key 调用。
- 开发测试阶段：在 .env 文件中配置 AI_API_KEY。
- 识别失败处理：提示用户选择（重试/跳过/手动录入）。

### 6.14 本地存储与数据生命周期
- 所有业务数据存储在本地 SQLite。
- 本地只保留业务数据与必要元数据。
- 不提供导出、导入。
- 不提供数据库加密。
- 卸载 App 或设备损坏会丢失数据，MVP 接受该风险。
- 图片仅用于当次识别，识别后立即删除。

### 6.15 软删除
- 当前周期内的业务实体采用软删除，记录 `deleted_at`。
- 历史周期数据自动归档，不支持软删除操作。
- 前端删除前强提示。
- 查询默认过滤 `deleted_at IS NULL`。
- 删除父实体时，应用层在同一事务内软删除所有子实体。

## 9. AI 识别与 Prompt 策略

### 9.1 输入
- 批量多图，最多 9 张。
- 每张图独立识别。
- 一张图默认一个购物单。
- AI 服务通过前端传入 API key 调用。
- 开发测试阶段：在 .env 文件中配置 AI_API_KEY。
- 识别失败处理：提示用户选择（重试/跳过/手动录入）。

### 9.2 输出要求
大模型需稳定输出 JSON，结构建议：

```json
{
  "source_image_index": 0,
  "merchant": "商家名称",
  "date": "2026-09-21",
  "items": [
    {
      "name": "牛奶",
      "quantity": 1,
      "unit_price": 15.00,
      "amount": 15.00,
      "tag": "食品"
    }
  ],
  "surcharges": [
    { "name": "配送费", "amount": 8.00 }
  ],
  "discounts": [
    { "name": "满减红包", "amount": -15.00 }
  ]
}
```

### 9.3 处理规则
- `items` 为商品原始信息。
- `surcharges` 与 `discounts` 仅用于计算，不持久化。
- 系统按商品原始金额比例摊入最终金额。
- 最终只保存 `final_amount`。
- 若只有一件商品，附加费/折扣直接计入该商品。
- 数量×单价与总价冲突时，以总价为准。

### 9.4 容错
- 识别失败可重试。
- 部分失败保留已识别结果。
- 全部失败转手动录入。
- 确认页允许增删改。

### 9.5 三级解析机制

**解析流程**：
1. 用户上传图片 → 优先调用AI在线解析
2. AI失败（断网/API key失效）→ 降级为本地解析（v4预留）
3. 本地解析失败 → 转手动录入

**来源字段说明**：
| 值 | 含义 | 场景 |
|---|---|---|
| manual | 手动输入 | 用户手动创建账目 |
| ai | AI在线解析 | 通过API调用大模型识别 |
| local | 本地解析 | 预留字段，用于后续本地OCR兜底 |

**统计用途**：
- 记录各来源占比，便于优化解析策略
- 后续可扩展parse_confidence、parse_duration_ms等统计字段

## 10. 非功能需求

### 10.1 金额精度
- 底层以"分"为单位存储。
- 展示以"元"为单位。
- 均摊除不尽时，差额优先给垫付人。
- 若垫付人不在参与人中，调整给参与人中金额最大者。
- 保证总账永远能平。
- 支持负数金额，用于折扣/退款，统计时冲减支出。

### 10.2 性能
- AI 识别通常 2–8 秒。
- 全屏同步等待，提示勿退出/熄屏。
- 批量多图显示进度。
- 本地账目、结算、时间线操作应即时响应。

### 10.3 安全与隐私
- 本地数据库不加密。
- 图片仅用于当次识别，识别后立即删除。
- 不保存原图。
- 不提供导出、导入。

### 10.4 可用性
- 核心记账功能不依赖网络。
- UI 中不出现"在线""离线"概念。
- AI 服务通过前端传入 API key 调用。
- 未保存内容不保证保留。

### 10.5 数据恢复
- 软删除。
- MVP 不做用户侧回收站。
- 本地数据丢失风险由用户承担。
- 不提供导出、导入备份。

### 10.6 并发
- MVP 为单设备本地使用。
- 不存在多人同时编辑。
- 本地操作按最后保存覆盖。

## 11. 边界场景与规则

| 场景 | 规则 |
|---|---|
| 单商品购物单 | 底层购物单，UI 降维为账目。 |
| 多图识别 | 一张图一个购物单，不跨图合并。 |
| 折扣/配送费 | 不生成独立账目，摊入商品最终金额。 |
| 付款人不在参与人 | 允许。 |
| 参与人为空 | 不允许，至少一个参与人。 |
| 删除购物单 | 强提示删除包含的全部商品，应用层级联软删除（仅限当前周期）。 |
| 0.01 差额 | 优先给垫付人；否则给参与人中金额最大者。 |
| 负数金额 | 支持，用于折扣/退款，统计时冲减支出。 |
| 重复上传 | 不自动去重，用户自行删除。 |
| 虚拟成员删除 | 历史账目保留引用，显示"已删除成员"。 |
| 历史周期数据 | 自动归档，不可编辑/删除，仅提供查看功能。 |
| 预算设置 | 用户可设置每月预算金额，默认自然月。 |
| 预算超支 | 仅警告不阻断，允许继续记账。 |
| 历史预算查看 | 支持查看过去几个月的预算使用情况（已归档）。 |
| 账本删除 | MVP 不做。 |
| 退出账本 | MVP 不做。 |
| 移除成员 | MVP 不做，仅软删除虚拟成员。 |
| AI 部分失败 | 保留已识别结果，可重试/跳过。 |
| AI 全部失败 | 转手动录入。 |
| 本地数据丢失 | 卸载、设备损坏会丢失，MVP 接受。 |
| 归档标签 | 标签被归档后不影响历史账目引用，新账目不可选择该标签。 |
| 删除自定义标签 | UI 仅提供归档操作，不提供删除。底层软删除仅用于数据清理。 |
