# 多人共享记账 App MVP PRD V1.0

## 1. 产品概述

### 1.1 产品定位
一款支持多人共享记账的独立 App，核心能力：

1. 多人共享账本，支持按商品/账目维度分摊。
2. 支持手动录入、编辑，以及从小票、购物截图批量 AI 识别录入。
3. 购物单作为多个账目的集合，底层为“账本 → 购物单 → 账目”，但 UI 上购物单与账目同层级展示。
4. 提供债务净额展示与转账/结算记录，不做最优转账算法。

### 1.2 MVP 目标
- 跑通：注册登录 → 创建/加入账本 → 录入/识别 → 分摊 → 保存 → 时间线展示 → 结算 → 转账核销。
- 验证：多人共享 + AI 小票识别 + 商品级分摊是否真实好用。
- 控制：不做权限、通知、离线、多币种、复杂统计等非核心功能。

### 1.3 核心用户场景
- 室友/情侣日常共同消费，按商品分摊。
- 朋友聚餐、旅行、合买，部分商品均摊、部分独享。
- 用户上传小票或电商订单截图，AI 识别为多个商品，确认后入账。
- 多人之间出现欠款，通过转账/结算记录核销。

## 2. 范围

### 2.1 MVP 包含
- 账号密码注册登录，手机/邮箱仅记录不验证。
- 自动分配账号 ID，用于检索和邀请。
- 创建多个账本，加入多个账本。
- 邀请方式：链接、二维码、账号 ID 检索。
- 账本时间线，展开展示账目/购物单。
- 手动录入单账目、多账目购物单。
- AI 批量多图识别，一张图默认一个购物单。
- 商品级付款人、参与人、分摊方式设置。
- 折扣/附加费摊入商品最终金额，不生成独立账目。
- 分类系统：系统预置分类，底层支持自定义，UI 暂不开放。
- 结算板：展示两两净额。
- 转账/结算记录：核销欠款，不计消费。
- 纯云端，需联网。
- 软删除，前端强提示。

### 2.2 MVP 不包含
- 本地业务数据存储、离线可用。
- 原图留存、凭证管理。
- 多币种、汇率换算。
- 推送通知、实时动态。
- 权限控制、角色管理 UI。
- 分类自定义 UI。
- 搜索、筛选、图表统计、数据导出。
- 回收站 UI。
- 忘记密码、账号验证、账号找回。
- 保存后拆分/合并购物单。
- 跨购物单批量编辑。
- 实时协同、冲突合并。
- 最优转账算法。
- 结算锁定期。
- 复杂折扣/附加费按高级规则分摊。

## 3. 术语与核心概念

| 术语 | 定义 |
|---|---|
| 账号 | 用户登录身份，包含自动分配的唯一账号 ID。 |
| 账本 | 多人共享记账的顶层容器。 |
| 账本成员 | 加入账本的用户。MVP 无权限区分。 |
| 购物单 | 一次购物或一张小票/截图的集合，底层包含多个账目。 |
| 账目/商品 | 最小记账单位，也是分摊基本单位。 |
| 付款人/垫付人 | 实际支付该账目金额的人。 |
| 参与人 | 需要承担该账目金额的人。 |
| 分摊方式 | 均摊、按比例、按金额。默认均摊。 |
| 转账/结算 | 特殊记录类型，表示用户之间资金转移，不计消费，只影响余额。 |
| 时间线 | 账本内按时间倒序展示账目/购物单的主界面。 |
| 结算板 | 展示“谁欠谁多少”或成员应收/应付的页面。 |
| 降维展示 | 单账目购物单在 UI 上不显示为购物单，而直接显示为账目。 |

### 3.1 层级关系
- 底层：账本 → 购物单 → 账目。
- UI：购物单与账目同层级展示。
- 单账目购物单：底层仍为购物单，UI 降维为账目。
- 多账目购物单：UI 显示为购物单，可展开查看子账目。

## 4. 用户角色与权限

### 4.1 MVP 权限
- 账本内所有成员权限相同。
- 所有成员均可创建、编辑、删除任意账目、购物单、转账记录。
- 删除前必须强提示。
- 后端预留 role 字段，MVP 不做权限控制 UI。

### 4.2 数据可见性
- 账本内所有成员可见该账本全部账目、购物单、结算记录。
- 加入账本后可见全部历史账目。
- 邀请时需提示“加入后可见全部历史账目”。

## 5. 核心业务流程

### 5.1 注册与登录
1. 用户注册：填写手机号或邮箱（二选一，必填且唯一，不验证）+ 密码。
2. 系统自动分配唯一账号 ID。
3. 登录：手机号/邮箱 + 密码。
4. MVP 不做忘记密码、找回密码、账号验证。

### 5.2 创建与加入账本
1. 用户可创建多个账本。
2. 创建者为账本成员。
3. 邀请方式：
   - 链接：7 天有效，可重复使用，创建者可关闭。
   - 二维码：同链接。
   - 账号 ID 检索：输入对方账号 ID，对方确认后加入。
4. 加入后可见全部历史账目。

### 5.3 手动录入单账目
1. 进入录入页。
2. Header：时间、付款人、备注/默认分摊规则。
3. Body：一行商品/账目。
4. 默认付款人=当前用户；默认参与人=账本全部成员；默认均摊。
5. 保存后：底层创建单账目购物单，UI 降维展示为账目。

### 5.4 手动录入多账目购物单
1. 进入录入页。
2. 填写第一行后点击“+ 添加新账目”。
3. 系统自动变为购物单模式。
4. 可设置购物单标题、整体备注。
5. 每个账目独立设置付款人、参与人、分摊方式。
6. 保存后生成一个购物单，包含多个账目。

### 5.5 AI 批量多图录入
1. 用户一次上传最多 9 张图片。
2. 全屏同步等待，提示“请勿退出或熄屏”。
3. AI 逐张识别。
4. 一张图默认生成一个购物单：
   - 图内多个商品 → 多商品购物单。
   - 图内只有一个商品 → 单商品购物单，UI 降维为账目。
5. 识别结果进入统一确认页，按图分组。
6. 用户可增删改、调分摊、改付款人、改分类。
7. 确认保存后才入账。
8. 单张失败可重试或跳过，已识别结果保留；全部失败可转手动录入。
9. MVP 不保存原图，识别后图片丢弃。

### 5.6 编辑与删除
- 所有成员可编辑/删除任意账目、购物单、转账记录。
- 修改/删除历史账目会影响当前余额，保存前强提示。
- 删除购物单时提示“确认删除此购物单及包含的 N 个商品吗？”
- 后端软删除，`is_deleted=1`。
- MVP 不做结算锁定期。

### 5.7 结算与转账
1. 结算板展示当前用户视角：
   - 你欠 X 多少。
   - X 欠你多少。
2. 全局视图展示每个成员应收/应付。
3. 不做最优转账算法。
4. 点击“我欠 B 150 元”可弹出“向 B 结清”。
5. 自动生成转账记录：金额 150，付款人我，收款人 B。
6. 转账记录不计消费，只影响余额。
7. 转账记录可编辑/删除，强提示会影响当前余额。

## 6. 功能需求详述

### 6.1 账号与登录
- 注册字段：手机号或邮箱（二选一）、密码。
- 手机/邮箱唯一，不验证。
- 密码 ≥6 位。
- 账号 ID 自动分配，唯一、不可改、可展示。
- 登录方式：手机号/邮箱 + 密码。
- 允许多设备登录。
- MVP 不做找回密码。
- 账号检索仅使用账号 ID，不使用手机/邮箱搜人。

### 6.2 账本管理
- 支持创建多个账本。
- 支持加入多个账本。
- 首页展示账本列表，最近访问优先。
- 账本字段：名称、创建者、创建时间、成员列表。
- MVP 不做删除账本、退出账本、移除成员。
- 可归档账本，归档后不在主列表优先展示。

### 6.3 邀请与加入
- 邀请链接：7 天有效，可重复使用，创建者可关闭。
- 二维码：内容同邀请链接。
- 账号 ID 检索：输入账号 ID，对方确认后加入。
- 加入前提示：加入后可见全部历史账目。
- 加入后成为账本成员。

### 6.4 购物单与账目
- 购物单字段：标题、商家、发生时间、创建者、默认付款人、默认参与人、备注、来源（手动/AI）。
- 账目字段：名称、数量、单价、最终金额、分类、付款人、分摊方式、备注。
- 数量、单价、总价均保存。
- 若数量×单价与总价冲突，以总价为准。
- 分摊以最终金额为准。
- 单账目购物单 UI 降维为账目。

### 6.5 统一录入/编辑/确认页
- 手动录入、AI 确认、编辑页 UI/UX 保持一致。
- 结构：
  - Header：时间、付款人、整体备注/默认分摊规则。
  - Body：动态清单流，每行一个商品/账目。
  - Footer：+ 添加新账目、总金额汇总。
- 每个商品行可展开编辑：
  - 名称、金额、分类、付款人、参与人、分摊方式。
- 默认值：
  - 付款人=当前用户/上传者。
  - 参与人=账本全部成员。
  - 分摊方式=均摊。
- 用户可批量应用默认值到当前所有商品，之后每个商品独立修改。
- 不搞父子覆写逻辑，每个商品生来独立。

### 6.6 分摊规则
- 分摊基本单位：商品/账目。
- 支持指定参与人。
- 支持分摊方式：
  - 均摊。
  - 按比例。
  - 按金额。
- 默认均摊。
- 按金额总和必须等于商品最终金额。
- 按比例总和必须为 100%。
- 付款人可以不在参与人中，例如 A 垫付但 B 独享。
- 均摊除不尽时：
  - 优先将差额分配给垫付人。
  - 若垫付人不在参与人中，则调整给参与人中金额最大者。
  - 保证总账永远能平。

### 6.7 折扣、配送费、附加费
- 不生成独立商品/账目。
- 不记录中间信息。
- 直接摊入商品最终金额。
- 规则：
  - 按各商品原始金额比例摊到每个商品。
  - 分位四舍五入。
  - 差额调整到金额最大的商品。
  - 若只有一个商品，直接计入该商品最终金额。
- 用户手动修改时，改的是商品最终金额。
- AI 可临时识别全局附加费/折扣用于计算，但保存时不持久化中间字段。

### 6.8 分类
- 分类打在账目/商品上，购物单不单独分类。
- 统计按子账目聚合。
- MVP 系统预置 10–15 个通用分类。
- 底层支持自定义分类，UI 暂不开放。

### 6.9 时间线
- 按日期倒序。
- 多商品购物单展开展示子账目。
- 子账目 ≤5 个：全量展开。
- 子账目 >5 个：显示前 3–4 个，末尾显示“... 等共 N 项商品（点击展开全部）”。
- 单账目购物单降维为账目展示。
- 同一批多图生成的多个购物单按创建时间倒序，独立展示，不显示“批次”。

### 6.10 结算板
- 当前用户视角：你欠 X / X 欠你。
- 全局视角：每个成员应收/应付。
- 不做最优转账算法。
- 点击债务可快捷生成转账记录。

### 6.11 转账/结算记录
- 特殊记录类型，不属于购物单消费。
- 字段：付款人、收款人、金额、时间、备注、创建者。
- 不计入消费统计，只影响余额。
- 可编辑/删除，强提示。

### 6.12 AI 识别
- 支持批量多图，单次最多 9 张。
- 格式：jpg/png/webp，单张 ≤10MB。
- 全屏同步等待，提示“请勿退出或熄屏”。
- 识别后进入统一确认页。
- 确认保存后才入账。
- MVP 不做草稿。
- 不保存原图。
- 单张失败可重试/跳过。
- 全部失败可转手动录入。

### 6.13 纯云端与离线
- 不做本地业务数据存储。
- 本地只保留登录态。
- 离线不可用。
- 无网不能登录、创建、识别、保存。
- 未保存内容不保证保留。

### 6.14 并发与刷新
- MVP 不做实时协同。
- 进入页面/下拉刷新获取最新数据。
- 多人同时编辑同一账目时，按最后保存覆盖，不做冲突合并。

### 6.15 软删除
- 后端软删除，`is_deleted=1`。
- 前端删除前强提示。
- MVP 不做回收站 UI。

## 9. AI 识别与 Prompt 策略

### 9.1 输入
- 批量多图，最多 9 张。
- 每张图独立识别。
- 一张图默认一个购物单。

### 9.2 输出要求
大模型需稳定输出 JSON，结构建议：

```json
{
  "source_image_index": 0,
  "merchant": "商家名称",
  "date": "2026-09-21",
  "items": [
    {
      "name": "牛奶",
      "quantity": 1,
      "unit_price": 15.00,
      "amount": 15.00,
      "category": "食品"
    }
  ],
  "surcharges": [
    { "name": "配送费", "amount": 8.00 }
  ],
  "discounts": [
    { "name": "满减红包", "amount": -15.00 }
  ]
}
```

### 9.3 处理规则
- `items` 为商品原始信息。
- `surcharges` 与 `discounts` 仅用于计算，不持久化。
- 系统按商品原始金额比例摊入最终金额。
- 最终只保存 `final_amount`。
- 若只有一件商品，附加费/折扣直接计入该商品。
- 数量×单价与总价冲突时，以总价为准。

### 9.4 容错
- 识别失败可重试。
- 部分失败保留已识别结果。
- 全部失败转手动录入。
- 确认页允许增删改。

## 10. 非功能需求

### 10.1 金额精度
- 底层以“分”为单位存储。
- 展示以“元”为单位。
- 均摊除不尽时，差额优先给垫付人。
- 若垫付人不在参与人中，调整给参与人中金额最大者。

### 10.2 性能
- AI 识别通常 2–8 秒。
- 全屏同步等待，提示勿退出/熄屏。
- 批量多图显示进度。

### 10.3 安全与隐私
- 密码哈希存储。
- HTTPS 传输。
- 账本数据仅账本成员可见。
- 图片仅用于当次识别，识别后不持久化。
- 纯云端，本地不缓存业务数据。

### 10.4 可用性
- 离线不可用。
- 无网提示。
- 未保存内容不保证保留。

### 10.5 数据恢复
- 软删除。
- 开发/运维可人工恢复。
- MVP 不做用户侧回收站。

### 10.6 并发
- 最后保存覆盖。
- 不做冲突合并。
- 进入页面/下拉刷新获取最新数据。

## 11. 边界场景与规则

| 场景 | 规则 |
|---|---|
| 单商品购物单 | 底层购物单，UI 降维为账目。 |
| 多图识别 | 一张图一个购物单，不跨图合并。 |
| 折扣/配送费 | 不生成独立账目，摊入商品最终金额。 |
| 付款人不在参与人 | 允许。 |
| 参与人为空 | 不允许，至少一个参与人。 |
| 分摊金额不等 | 不允许保存，必须等于最终金额。 |
| 比例总和不为 100% | 不允许保存。 |
| 历史账目修改 | 允许，强提示影响余额。 |
| 删除购物单 | 强提示删除包含的全部商品。 |
| 0.01 差额 | 优先给垫付人；否则给参与人中金额最大者。 |
| 负数金额 | 支持，用于折扣/退款，统计时冲减支出。 |
| 重复上传 | 不自动去重，用户自行删除。 |
| 离线 | 不可用。 |
| 多人同时编辑 | 最后保存覆盖。 |
